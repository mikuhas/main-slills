##### P1-6 [MUST] 途中で失敗すると注文だけが残る

| 項目 | 内容 |
| :--: | --- |
| 指摘レベル | [MUST] |
| 箇所 | `sample/file/review/orderController.ts:46-63` |
| 問題 | 「注文を登録」「ランクを加算」「監査ログを記録」の3つのDB更新を順番に実行しており、まとめて扱う仕組み（トランザクション: 複数の更新を全部成功か全部取り消しに揃える仕組み）が無い。 |

**改善案**: 3つの更新を1つのトランザクションで囲み、途中で失敗したら全体をロールバックする。DBライブラリの `transaction()` に処理を渡す形にする。

**修正例**:

```diff
-    const order = await db.raw("INSERT INTO orders ...");
-    if (flag2) {
-      await this.doStuff(order[0], body.userId);
-    }
+    const order = await db.transaction(async (trx) => {
+      const created = await orderRepository.create(trx, { userId, total });
+      if (isHighValueOrder) {
+        await this.grantRankAndRecordAudit(trx, created, userId);
+      }
+      return created;
+    });
```

##### P2-1 [MUST] URL1本で注文テーブルを消せる

| 項目 | 内容 |
| :--: | --- |
| 指摘レベル | [MUST] |
| 箇所 | `sample/file/review/orderController.ts:10,16,17,47,62,63` |
| 問題 | URLパラメータやリクエストボディの値を、文字列連結でSQL文に埋め込んでいる（SQLインジェクション: 値の隙間にSQLの断片を紛れ込ませ、意図しない命令を実行させる攻撃）。 |
| 影響 | `userId` に常に真になる条件を渡すだけで他人の注文が全件見える。文の区切り記号のあとにテーブル削除の命令を続ければ、注文テーブルごと消せる。認証を突破する必要はなく、URLを1本叩くだけで成立する。 |

**改善案**: 全クエリを `?` プレースホルダに値を渡すパラメータバインドへ書き換える。あわせてSQLの文字列連結を lint で検出できるようにする。

**修正例**:

```diff
-    const rows = await db.raw(
-      "SELECT * FROM orders WHERE user_id = '" + uid + "' ORDER BY created_at DESC LIMIT 100"
-    );
+    const rows = await db.raw(
+      "SELECT * FROM orders WHERE user_id = ? ORDER BY created_at DESC LIMIT 100",
+      [uid]
+    );
```
