# 画面デザイン

## 概要
この skill は `frontend-design` と `ui-ux-pro-max` を継承し、この skill に書いた項目で上書きして使う。
配色・書体・余白のスケール・UX の定石は `ui-ux-pro-max` に従う。この skill は、継承元に無い**業務画面（管理画面・ダッシュボード）の定石**と、`ui-ux-pro-max` を業務画面で使うときの注意だけを足す。
文中の `` `input-labels` `` のような記号は、`ui-ux-pro-max` の `references/quick-reference.md` のルール名。

---

## 継承元

| skill（一覧での名前） | 従う範囲 |
| --- | --- |
| `frontend-design:frontend-design` | 見た目の方向性・動き・画面の文言 |
| `ui-ux-pro-max:ui-ux-pro-max` | 配色・書体・余白のスケール・UX の定石・アクセシビリティ・グラフの種類 |

### 継承のルール
1. 作業を始めたら、ユーザーへの質問やファイルの確認より前に、上の2つを表の順に読み込む（質問だけで止まる場合も先に読み込む）。
2. 見つからない場合は、次の1行を伝えて作業を続ける。
   - 「frontend-design が見つからないため、この skill の内容だけで作ります（導入: `/plugin install frontend-design@claude-plugins-official`）」
   - 「ui-ux-pro-max が見つからないため、この skill の内容だけで作ります（導入: `/plugin marketplace add nextlevelbuilder/ui-ux-pro-max-skill` → `/plugin install ui-ux-pro-max@ui-ux-pro-max-skill`）」
3. この skill に書いた項目は継承元より優先する。書いていない項目は、表の「従う範囲」でその項目を担う skill に従う。どちらの範囲にも無ければ、見た目は `frontend-design`、使いやすさは `ui-ux-pro-max` に従う。
4. 配色は `ui-ux-pro-max` に従い、`frontend-design` の配色の手順（4〜6色を自分で組む）は使わない。
5. 同じプラグインの他の skill（`ui-ux-pro-max:design`・`ui-ux-pro-max:ui-styling` など）は読み込まない。`dataviz` など別の skill は、その説明どおりに読み込んでよい。

## ペルソナ
`frontend-design` のペルソナ（どの顧客にも似ない見た目を、意図を持って選ぶデザインスタジオの責任者）を継承し、次の2点を加える。

- **業務画面での優先順位**: 独自性より「毎日何時間も使う担当者が、速く・間違えずに操作できること」を優先する。独自性は書体と見出しまわりで出し、表・フォームは「3. 業務画面の部品」の定石どおりに作る。
- **言葉遣い**: 質問・報告は断定形の日本語で簡潔に書く。デザインの理由を説明するときは1行にとどめる。

## 対象外（Non-goals）
以下は**出力に含めない**。

| 含めないもの | 代わりに |
| --- | --- |
| ダークモード対応（依頼が無い場合） | ライトモードだけを作る |
| デザイン原則・色彩理論の解説 | 理由は1行にとどめる |
| 業務画面のスマホ向けレイアウト（依頼が無い場合） | PC 幅（1280px）を基準に作り、狭い幅では表を横スクロールにする（`mobile-first`・`horizontal-scroll` より優先） |
| 業務画面の LP 向けの構成（ヒーロー・特徴紹介・CTA の並び） | 「3. 業務画面の部品」の構成で作る |
| 業務画面の装飾だけの動き（入場アニメーション・視差効果など） | 状態の変化（開閉・読み込み）を伝える動きだけにする（`motion-meaning`） |
| ロゴ・イラスト・写真の作成や選定 | 置き場所だけを確保したプレースホルダー |

## デザインの基礎

デザインの基本4原則を、この skill では次の基準で判定する。

| 原則 | 判定の基準 |
| --- | --- |
| 近接（関連する要素を近くに） | まとまりの中の間隔 < まとまりどうしの間隔（`whitespace-balance`・`field-grouping`） |
| 整列（端の線を揃える） | 画面の左端の線を増やさない。フォームのラベル・入力欄・ボタンは同じ左端に揃える。表の数値は右揃え |
| 反復（同じルールを繰り返す） | 同じ種類の部品は、全画面で同じ見た目・同じ位置にする（`consistency`・`navigation-consistency`）。余白・文字サイズはスケールからだけ選ぶ（`spacing-scale`・`font-scale`） |
| 対比（重要度にメリハリ） | 重要度は大きさ・太さ・余白で付ける（`visual-hierarchy`・`weight-hierarchy`）。主な操作は1画面に1つ（`primary-action`） |

## 確認してほしいこと

### 1. 使う人の確認
「社内の担当者が使う業務画面」か「一般の利用者向けの画面」かが依頼文とプロジェクトから分からない場合は、最初に1問で確認する。業務画面なら2〜4を適用し、一般向けの画面は継承元に従う。
- 例:「ホテルの宿泊プラン一覧画面」は、宿泊客向けの予約サイトか、ホテルの管理画面かが分からないので確認する。
- 例:「受注一覧の管理画面」は業務画面と分かるので確認しない。

### 2. `ui-ux-pro-max` の使い方（業務画面）
| 状況 | 動き |
| --- | --- |
| プロジェクトにデザインシステム（`design-system/*/MASTER.md`、色・余白の CSS 変数、Tailwind のテーマなど）がある | それに従う。`--design-system` は実行しない |
| 無い | `--design-system` に `--density 8 --motion 2` を付けて実行する |

- クエリは画面の種類で作る（例: `"enterprise back office dashboard"`）。業務の名詞（`order`・`hotel`・`restaurant` など）を入れると、その業種の一般向けのデザインが返るため入れない。
- 結果の Pattern（Hero・Features・CTA などのセクション構成）は使わない。構成は「3. 業務画面の部品」に従う。
- 結果の Style が装飾的なもの（Glassmorphism・Brutalism など）なら、`ui-ux-pro-max` の手順どおり1回だけ `minimal` などを足して再検索する。

### 3. 業務画面の部品

#### 一覧画面の構成（上から順に）
1. ページ見出しと主な操作（例: 新規登録）を同じ行に置き、主な操作は右端にする。
2. 絞り込み。適用中の条件が一目で分かるようにし、「条件をクリア」を置く。
3. 件数（例: 「128件」）。
4. 表。
5. ページ送り（表の下の右端）。

#### 表
| 項目 | 基準 |
| --- | --- |
| 揃え | 数値・金額は右揃え（`number-tabular` も付ける）、それ以外は左揃え。見出しセルも列の値と同じ揃えにする |
| 区切り | 行の区切りは横線だけ。縦線・しま模様（1行おきの背景色）は付けない |
| 行の高さ | 1画面の中で変えない |
| 単位 | 見出しに書く（例: 「金額（円）」）。セルには数値だけを書く |
| 行ごとの操作 | 右端の列に置く。3つ以上になったら「…」メニューにまとめる（`overflow-menu`） |
| 長い表 | 見出し行を固定する。列が画面に収まらなければ、先頭列（受注番号などの識別子）を固定して横スクロールにする |
| 並び替え | 並び替えられる列だけ、見出しに向きのアイコンを付ける |

#### フォーム
ラベル・エラー・必須の印・送信中の表示は `ui-ux-pro-max` の「8. Forms & Feedback」に従い、次を加える。

| 項目 | 基準 |
| --- | --- |
| ラベルの位置 | 入力欄の上 |
| 並び | 1列で縦に並べる。横に並べるのは、組で入力する短い項目（姓と名、開始日と終了日）だけ |
| 幅 | 入る値の長さに合わせる（郵便番号・数量を全幅にしない） |
| ボタン | フォームの末尾に、入力欄と同じ左端で揃える。主な操作を左、キャンセルをその右に置く |

#### ダッシュボード
- 最上段に KPI を3〜5個並べる。数値を画面で最も大きい文字にし、比較（前月比など）を数値の下に添える。
- グラフは KPI の下に置く。種類と描き方は `dataviz`（無ければ `ui-ux-pro-max` の `--domain chart`）に従う。

### 4. 状態の表示
`empty-states`・`progressive-loading`・`error-recovery`・`confirmation-dialogs` に従い、データを表示する画面では次の状態をすべて作る。

| 状態 | 出すもの |
| --- | --- |
| データが0件（まだ登録が無い） | 何が無いかと、最初の操作（例: 「顧客はまだ登録されていません」＋「顧客を登録」） |
| 絞り込みの結果が0件 | 条件に合うものが無いことと「条件をクリア」。登録は促さない |
| 読み込み中 | 表は行の形のスケルトン |
| 読み込みの失敗 | 何が起きたかと「再読み込み」。エラーコードだけを出さない |
| 取り消せない操作（削除など） | 確認ダイアログで対象の名前を示す（例: 「受注 A-1024 を削除します」） |

## よくある誤り
| 誤り | 正しい動き |
| --- | --- |
| 継承元を読み込まずに作り始める | 「継承のルール」の1に従い、先に読み込む |
| `frontend-design` の手順で配色を組む | 配色は `ui-ux-pro-max` に従う |
| プロジェクトにデザインシステムがあるのに `--design-system` を実行して上書きする | 既存のデザインシステムに従う |
| クエリに業務の名詞（`order` など）を入れ、飲食店向けのデザインが返る | 画面の種類でクエリを作る |
| 業務画面で `--density` を付けずに実行し、余白の広い LP 向けのスケールになる | `--density 8` を付ける |
| 結果の Pattern に従い、管理画面にヒーローを置く | Pattern は使わず、「3. 業務画面の部品」の構成で作る |
| 表の数値・金額を左揃えにする | 右揃えにし、`number-tabular` を付ける |
| 0件のとき「データがありません」とだけ出す | 登録が0件か絞り込みの結果が0件かで出し分け、次の操作を出す |
| 業務の表をスマホ幅に収めるため、行を縦積みのカードに崩す | PC 幅を基準にし、狭い幅では横スクロールにする |

## 出力例（Few-Shot）
確認の出し方・`ui-ux-pro-max` の使い方・業務画面の組み方の基準。形式と分量をこの例に合わせる。

### 例1: 使う人が分からない → 1問で確認する

**入力**

> ホテルの宿泊プラン一覧画面を作って

（プロジェクトからは、予約サイトか管理画面かが分からない）

**出力**

```
この画面を使うのはどちらですか。
- 宿泊客（予約サイトのプラン一覧）
- ホテルの担当者（管理画面のプラン一覧）
```

### 例2: 業務の一覧画面 → 業務向けのクエリで実行し、定石どおりに組む

**入力**

> 受注一覧の管理画面を作って

（プロジェクトにデザインシステムは無い）

**出力**

```bash
python "<ui-ux-pro-max の場所>/scripts/search.py" "enterprise back office dashboard" --design-system --density 8 --motion 2 -p "Order Admin"
```

結果の Pattern（Hero + Features + CTA）は使わず、色・書体・余白のスケールだけを取り入れて、一覧画面の構成で組む。

```html
<main class="page">
  <header class="page__head">
    <h1>受注一覧</h1>
    <button class="btn-primary">受注を登録</button>
  </header>
  <form class="filters"><!-- ステータス・期間 --><button type="reset" class="btn-link">条件をクリア</button></form>
  <p class="count">128件</p>
  <table class="table">
    <thead>
      <tr><th>受注番号</th><th>顧客名</th><th class="num">金額（円）</th><th>ステータス</th><th></th></tr>
    </thead>
    <tbody>
      <tr><td>A-1024</td><td>山田商店</td><td class="num">128,000</td><td>出荷待ち</td><td><!-- 操作 --></td></tr>
    </tbody>
  </table>
</main>
```

```css
.page__head { display: flex; justify-content: space-between; align-items: center; margin-bottom: var(--space-2xl); }
.table th, .table td { padding: var(--space-lg) var(--space-xl); border-bottom: 1px solid var(--color-border); }
.table .num { text-align: right; font-variant-numeric: tabular-nums; }
```

絞り込みの結果が0件のときは、表の代わりに「条件に合う受注はありません」と「条件をクリア」を出す。
